# combination on Raspberry Pi OS Bookworm. RPi.GPIO is deliberately

# armv7 wheels via the piwheels index already configured in the
# Dockerfile, so this doesn't reintroduce a long compile on the Pi.

# Voice control (voice_control_service.py). Wake word via Vosk's
# grammar-constrained recognition, NOT openWakeWord and NOT Porcupine -
# both ruled out by real, verified findings, not preference.
# openWakeWord hard-requires either onnxruntime or tflite-runtime on
# Linux, and neither currently installs on this Pi's architecture
# (armv7): onnxruntime has never published official armv7 wheels
# (confirmed - piwheels' own project page for it shows zero files,
# since piwheels builds from PyPI's sdist and onnxruntime doesn't ship
# one usable for that), and tflite-runtime was renamed to
# ai-edge-litert with a different import path. Porcupine's wheel
# genuinely does bundle working Raspberry Pi binaries (confirmed by
# inspecting it) - but it requires a Picovoice Console account for even
# a free AccessKey, and that signup wasn't available here. Vosk needs
# no account or key at all (just downloads its own model from a public
# URL on first run - see voice_control_service.py's VOSK_MODEL_DIR),
# and publishes a REAL armv7l wheel directly on PyPI - confirmed with
# `pip download vosk --platform linux_armv7l`, not assumed. Speech-to-
# text and text-to-speech go through Groq instead of running locally -
# see voice_control_service.py's module docstring for why that split,
# not everything local, is the realistic choice on a Pi 2.
vosk==0.3.45
sounddevice==0.5.5
groq==1.6.0
