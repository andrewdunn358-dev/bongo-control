Subject: [PATCH 1/4] #46 Stage 1 - one Theme, one rendering path

Home renders one themed path for every theme and every orientation.
Adventure's React cockpit and its privileged CSS are deleted; Adventure
is now layout/builtins/adventure.home.json, validated by the same
parseLayout that validates an installed .vanos-theme. A TypeScript
object literal bypassed the validator, so ADVENTURE_HOME could express
what a package would have been refused for - the built-ins were not
actually proof that the schema worked. Now there is one gate and both
sources go through it.

Portrait no longer discards the selected theme. It rendered Instrument's
page with zero renderer slots regardless of what was chosen, which also
affected Control; Control now renders its own page in portrait.

A package whose composition names a cockpit this build cannot draw is
refused at import, with a message naming the cockpits that can, instead
of being accepted and ignored. Unknown widget ids are reported at import
and again in the theme list.

The JSON-only localStorage theme mechanism is removed: parseThemeFile,
saveCustomTheme, loadCustomThemes, deleteCustomTheme and the "Add theme
file..." input. A Theme is an installed .vanos-theme package and nothing
else, and no UI text distinguishes built-in from installed. Anyone who
had browser-local JSON themes gets one dismissible notice rather than
silently losing entries.

Auto-fit now clears --fit and data-fit-step when disabled instead of
returning early, so a mode change cannot leave stale inline values on
the element.

Measured against main, demo builds, both served locally: Adventure's
landscape and desktop geometry is unchanged at all five viewports -
identical content height, overflow, --fit, ladder step and card geometry
hash, with only the surface class differing. Instrument is identical at
all six. Adventure at 363x737 goes from vi-page with 0 renderer slots to
vl-surface with 10.

Disabling auto-fit in portrait was tried and reverted: the ladder turns
out to be carrying the narrow column as well as the height, and
unfitted at 363px the headline collides with the quote and the footer
spills. That is width work in the widget container queries, not fit
work.

tests/builtin-compositions.test.mjs asserts every built-in composition
validates against the real registry, and that assertCompositionSupported
refuses an unsupported cockpit and one naming none. At runtime a failing
built-in is logged and skipped so the van still starts, so CI is the
only place that failure can be loud - and neither layout test was
running in CI, so safety.yml now runs both.
