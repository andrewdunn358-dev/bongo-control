Measured, the previous degrade was not the graceful one its comment
claimed. With adventure.home.json made invalid, a build logged the
failure and then rendered a BLANK cockpit: no surface element, zero
slots, zero cards. load() dropped the failed entry, builtinComposition
returned undefined, resolveComposition returned undefined, Home took the
legacy branch, and Adventure has no component.

A failed built-in now degrades to an emergency composition: battery and
position footer, full width, nothing conditional. It is not selectable
and is not in SOURCES - it is only ever reached by failure - and it goes
through the SAME parseLayout against the SAME registry as everything
else. A hand-written literal here would have been exactly the
ADVENTURE_HOME mistake, unvalidated precisely where the guarantee
matters most.

Failing and having no built-in stay different things. An id in SOURCES
that fails keeps an entry and stays in the themed path; an id with no
source at all still resolves to undefined so Instrument and Control keep
their components. Conflating them would either blank Adventure on a bad
JSON or take Instrument's cockpit away.

There is deliberately no second fallback. If the emergency composition
itself fails to validate it is logged and nothing is substituted,
because inventing a rescue that bypasses the validator is worse than a
loud absence. CI fails on it either way.

loadCompositions is exported so the FAILURE path is testable with a
deliberately broken source. Asserting only that the shipped JSON parses
would not have caught the blank cockpit, because the shipped JSON does
parse. Tests now assert: the emergency composition validates and every
widget it names is registered; an invalid built-in resolves to it rather
than to undefined or an empty layout; both the failure and the
substitution are logged; and an unmigrated appearance still resolves to
undefined. Verified in a browser: a corrupted built-in went from no
surface and 0 slots to vl-surface with 2 slots drawing the battery.

Stage 1 build.
