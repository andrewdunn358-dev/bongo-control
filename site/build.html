Build your own VanOS

Everything you need to run the dashboard in a real van — from the Raspberry Pi up to the relays.

There is deliberately no OBD / engine diagnostics. The reference Bongo has no OBD port, so rather than fake it, that whole domain is out of scope.

Raspberry Pi setup

Flash Raspberry Pi OS (64-bit recommended on Pi 4/5; 32-bit is fine on a Pi 2/3), enable SSH, and get it on your network. Then install Docker and Docker Compose:

curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # then log out and back in

Install VanOS

git clone https://github.com/andrewdunn358-dev/bongo-control.git
cd bongo-control
docker compose up -d --build

That's it. Open http://<pi-address>:8090 and you'll have the dashboard running on simulated data straight away — real hardware slots in from there.

  • Frontend: http://<pi>:8090
  • Backend API + docs: http://<pi>:8000/docs

Configuration

Most of this is optional and can be set live in Settings → Integrations from the dashboard itself — your OpenStreetMap contact email and your Anthropic API key — with no file editing and no restart. They're stored on the Pi in data/config.json, and the API key is write‑only (never returned by the app). VanOS ships with no personal details baked in; you supply your own.

If you'd rather set defaults up front, copy the example environment file and edit what you need — the defaults work out of the box:

cp .env.example .env

Victron solar (Bluetooth)

VanOS reads a Victron SmartSolar MPPT over Bluetooth Low Energy — no wiring to the Pi. You'll need the device's instant readout encryption key from the VictronConnect app (Product info → Instant readout via Bluetooth). Add the MAC address and key to your config, and the Victron plugin publishes battery voltage and solar production onto the same bus the simulation used.

Confirmed working against a real SmartSolar MPPT from inside the container on a Raspberry Pi. See docs/victron_ble_integration.md in the repo for the exact steps and troubleshooting.

Temperature sensors (1-Wire)

Enable 1-Wire on the Pi (dtoverlay=w1-gpio in /boot/config.txt), wire your DS18B20 probes to GPIO4 with a 4.7kΩ pull-up, and they're detected automatically. No probes? The plugin simply reports nothing — it never invents a temperature.

Relays (GPIO switching)

Wire a relay board to the Pi's GPIO. The relays sit in parallel with the van's physical wall switches, so the dashboard knows what it told a relay to do (its commanded state) but not whether the circuit is physically live — there's no sense line back, and VanOS is honest about that distinction. Control them from the Switches page (gated by the app password if you set one).

An elevating roof is a special case: its two relays are excluded from the plain Switches page entirely and only movable from a dedicated Roof screen using press-and-hold — a watchdog drops the relay if the app stops hearing from your finger, so there's no failure mode where the motor keeps running unattended.
Mains or high-current loads should be switched through appropriately rated relays/contactors, not the GPIO pins directly. Wire safely.

Camera

Plug in a USB webcam and pass it through (the compose file maps /dev/video0 by default). The camera view uses snapshot polling so it's reliable on phones and tablets alike, and snapshots you capture are stored on the Pi. See docs/cctv_camera_setup.md.

Remote access (Cloudflare Tunnel)

To reach the dashboard from anywhere over HTTPS — no port forwarding, works behind CGNAT — run the optional Cloudflare Tunnel. Put your tunnel token in .env and bring it up with the profile:

docker compose --profile cloudflare-tunnel up -d --build

Full walk-through in docs/remote_access_cloudflare_tunnel.md.

Updating

cd ~/bongo-control
git pull
docker compose --profile cloudflare-tunnel up -d --build --remove-orphans

The --build flag is what rebuilds the app and picks up changes. On mobile the installed dashboard updates itself automatically within a few minutes of a new deploy.
